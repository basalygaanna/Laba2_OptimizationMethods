# Лабораторная работа № 2 — вариант 18

**Тема:** переброска аварийных бригад после ЧС.  
**Цель модели:** минимизировать суммарное время развёртывания бригад.

## Состав модели

- 5 баз аварийных бригад;
- 6 точек ЧС;
- дуга от каждой базы к каждой точке ЧС;
- стоимость дуги — время прибытия одной бригады (минуты);
- запас базы — доступное число бригад;
- спрос точки ЧС — необходимое число бригад;
- пропускная способность дуги — максимальное число бригад по маршруту.

Переменная `x[i,j]` — количество бригад, направленных с базы `i` в точку `j`.

Целевая функция:

`min sum(time[i,j] * x[i,j])`

Ограничения:
- сумма отправленных с каждой базы бригад не превышает её запас;
- каждая точка ЧС получает ровно требуемое число бригад;
- поток по каждой дуге находится между нулём и пропускной способностью.

Потоковые переменные непрерывные, как требует ЛП-постановка лабораторной работы.

## Данные

Данные варианта генерируются один раз с помощью `numpy.random.default_rng(10201)` и сохраняются в `data/generated_data.json`. Параметры индивидуализации: `N=1`, `Q=2` (группа 527), `Y=26`; seed = `10000 + 100*Q + N = 10201`.

Синтетические параметры:
- время на дуге: целое число от 20 до 90 минут;
- запас базы: от 4 до 7 бригад;
- спрос точки ЧС: от 2 до 4 бригад;
- пропускная способность дуги: от 1 до 4 бригад.

## Формальная постановка

Индексы: `i` — база, `j` — точка ЧС.

Параметры:
- `t[i,j]` — время прибытия одной бригады, мин;
- `s[i]` — запас бригад на базе, бригад;
- `d[j]` — потребность точки ЧС, бригад;
- `u[i,j]` — пропускная способность дуги, бригад.

Переменные: `x[i,j] >= 0` — число бригад, направляемых по дуге (в ЛП допускается непрерывное значение).

Модель:

```text
min  sum_i sum_j t[i,j] * x[i,j]

sum_j x[i,j] <= s[i]                 для каждой базы i
sum_i x[i,j]  = d[j]                 для каждой точки j
0 <= x[i,j] <= u[i,j]                для каждой дуги (i,j)
```

## Выполненные обязательные эксперименты

1. Базовое решение.
2. Независимая проверка балансов и ограничений на дугах отдельным кодом NumPy с допуском `1e-7`.
3. Отказ наиболее загруженной дуги и повторное решение.
4. Рост спроса каждой точки на 20% и повторное решение.
5. Определение насыщенных дуг как узких мест.
6. Сравнение с простой жадной эвристикой: сначала используются дуги с наименьшим временем.

Результаты экспериментов записываются в `results/`, лог HiGHS — в `logs/solver.log`.

## Интерпретация

Целевая функция измеряется в бригадо-минутах: сумме времени прибытия, умноженного на количество направленных бригад. Это не время прибытия последней бригады, а суммарный показатель затрат времени по всем назначениям.
